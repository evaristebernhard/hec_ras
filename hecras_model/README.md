# GanjiangWestBridge HEC-RAS 7.0.1 model

## Model scope

This is the validated **1D steady-flow equivalent-blockage screening model** for the Ganjiang West Branch bridge reach. It is not yet an explicit HEC-RAS Bridge/Culvert model and must not be used to infer local pier vortices or scour depth.

## Inputs

- `GanjiangWestBridge.prj`
- `GanjiangWestBridge.f01`: Q = 26,000 m³/s, downstream known WSE = 22.049342 m
- `GanjiangWestBridge.g01` / `p01`: current surveyed bed, 360 m² equivalent blockage
- `GanjiangWestBridge.g02` / `p02`: 0.5 m protection, 380 m² equivalent blockage
- `GanjiangWestBridge.g03` / `p03`: 1.0 m protection, 390 m² equivalent blockage
- `GanjiangWestBridge.g04` / `p04`: 2.0 m protection, 410 m² equivalent blockage
- `GanjiangWestBridge.g05` / `p05`: centre constrained design-bed screening reconstruction, 280 m² blockage
- `GanjiangWestBridge.g06` / `p06`: local design-bed reconstruction sensitivity
- `GanjiangWestBridge.g07` / `p07`: distributed design-bed reconstruction sensitivity

The design-bed geometries are constrained reconstructions, not an original complete design-bed line recovered from CAD. They use the CAD design mud elevations at piers 15/16/17 plus the table-2 target net conveyance area of 5,700 m².

## Equivalent-blockage v2 convention

The obstruction **lateral width** is solved so that its submerged area at the CAD-labelled flood level 22.190 m equals the target blockage area.

The obstruction **top elevation** is deliberately set to a numerical sentinel of 50 m so HEC-RAS cannot artificially pass flow over the equivalent pier blockage when modeled WSE exceeds 22.190 m. The 50 m value is not a physical bridge-deck or pier elevation.

The original pre-fix result baseline, where the obstruction top was 22.190 m, is retained only as a historical artifact in `results/hecras_steady_four_cases_baseline_20260830.csv`. The corrected active baseline is `results/hecras_steady_four_cases_baseline_v2_20260830.csv`.

## Computed artifacts and validation

The `.r##`, `.O##`, `.g##.hdf`, and `.p##.hdf` files were generated by HEC-RAS 7.0.1 on Windows on 2026-08-30. Process exit code alone is not accepted as validation. The extractor requires:

- HDF root attribute `Units System = SI Units`;
- RS=500 `Obstr Block Mode = 1`;
- `Finished Steady Flow Simulation` in compute messages;
- no `warning` or `error` in the compute messages.

The corrected main-model p01-p04 key WSE values were independently reproduced by the separate downstream-boundary-sensitivity project to within 1e-6 m before the v2 parity baseline was frozen.

## Rebuild and extract

```bash
.venv/bin/python scripts/recover_design_bed.py
.venv/bin/python scripts/build_hecras_project.py
# Run p01-p07 with HEC-RAS 7.0.1 on Windows.
.venv/bin/python scripts/extract_hecras_steady_results.py
```

## Principal results

- `results/hecras_steady_four_cases.csv`: full-section p01-p04 results
- `results/hecras_steady_five_cases.csv`: key RS=600/500 comparison for the five main cases
- `results/hecras_steady_validation_all_plans.csv`: validation for p01-p07
- `results/hecras_design_bed_sensitivity.csv`: p05-p07 reconstruction sensitivity
- `results/hecras_p01_p04_parity_v2.csv`: corrected-model parity check

The separate `hecras_boundary_sensitivity/` project and `results/hecras_boundary_sensitivity*.csv` evaluate downstream known-WSE uncertainty at ±0.50 m without altering this main model.
